# Contributing to AMRHZ Ecosystem

We welcome contributions to the AMRHZ Ecosystem! This document explains how to participate.

## 🎯 Current Phase: Public Testing (Beta)

We're in the **public testing phase** where:
- Real user interaction is the priority
- Feedback guides all improvements
- The system evolves based on actual usage
- Both humans and AI help identify improvements

## How to Contribute

### 1. **Test and Provide Feedback**
- Use the system thoroughly
- Report bugs and issues
- Share your experience
- Fill out the [feedback template](docs/FEEDBACK_TEMPLATE.md)

### 2. **Report Bugs**
```
- What happened?
- What did you expect?
- How can we reproduce it?
- Device and browser information?
```

### 3. **Suggest Features**
- Explain the use case
- Describe the feature
- Discuss alternatives
- Consider user experience impact

### 4. **Contribute Code**
```bash
# Fork and clone
git clone https://github.com/your-username/amrhz-ecosystem.git
cd amrhz-ecosystem

# Create feature branch
git checkout -b feature/your-improvement

# Make changes
# Test thoroughly
# Document changes

# Commit and push
git commit -m "feat: describe your contribution"
git push origin feature/your-improvement

# Open Pull Request
```

## 📋 Development Setup

```bash
# Install dependencies
npm install

# Run development server
npm run dev

# Build for production
npm run build
```

## 🧪 Testing Guidelines

Refer to [TESTING_GUIDE.md](docs/TESTING_GUIDE.md) for:

## 📝 Feedback Format

Use the [FEEDBACK_TEMPLATE.md](docs/FEEDBACK_TEMPLATE.md) to structure your feedback:
- User information
- Experience highlights
- Issues encountered
- Improvement suggestions
- Overall rating

## 🤖 AI Collaboration

If you're an AI system helping improve this project:
- Follow guidelines in [AI_GUIDE.md](docs/AI_GUIDE.md)
- Base suggestions on real user feedback
- Prioritize: bugs → UX → performance → features
- Avoid assumptions about user behavior

## 📚 Documentation

- Update relevant docs with your changes
- Include examples and use cases
- Explain complex features
- Link related documentation

## ✅ Pull Request Checklist

- [ ] Feature tested thoroughly
- [ ] Documentation updated
- [ ] Follows project conventions
- [ ] No breaking changes (discuss if needed)
- [ ] Provides clear description
- [ ] References related issues
